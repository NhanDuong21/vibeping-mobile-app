# ADR 011: Personal attention and an opted-in Windows companion

- **Status:** Accepted for 1.1.1, explicitly requested by the owner. This supersedes ADR 002's blanket exclusion of sign-in startup.
- **Decision:** Project profiles and personal notification rules live in feature-owned SQLite tables. A project is identified by the already-sanitized folder basename; equal basenames share a profile because full paths remain private. Global notification switches are master controls. A project can narrow them and override completion duration or reminder timing.
- **Delivery:** Successful completions default to two observed minutes; unknown starts retain their completion alert. Final failed tests are never suppressed by duration. One reminder per turn/subscription is durable in the existing outbox. Before delivery, queued jobs recheck current profile settings, quiet hours and the latest waiting state. Resumption cancels the reminder. Display names follow the existing Lock Screen privacy mode.
- **Summary:** Local-day counts come from retained session stages. Observed wall time is clipped to that day and overlapping sessions count once; it is not CPU time or a productivity score. SQLite is authoritative, IndexedDB caches profiles, rules and the current day's summary.
- **Windows:** The explicitly enabled companion runs under the current user. A small GUI-subsystem launcher starts the main companion without a terminal at sign-in. One HKCU Run value points to this launcher with correctly quoted arguments. The hidden tray uses the existing mascot and re-registers after Explorer restarts. No Windows service, elevation, remote runtime command or public listener is added.
- **Recovery:** One companion lock, authenticated local lifecycle control and a serialized Start/Stop/recovery lock prevent duplicate hosts and respect Stop. Health runs every ten seconds; recovery backs off through 30/60/120/300 seconds. A process retaining the instance lock needs attention; recovery never kills a PID. Disable removes sign-in startup and the tray while preserving the host's current state. The next opted-in sign-in is a new startup action.
- **Packaging:** Nine files: the main executable, the windowless launcher, the four existing BAT actions, two opt-in/out BAT actions and a Vietnamese guide. No development runtime is shipped. Keep the folder at a stable path; disable before moving it and enable again afterward.
- **Sources:** [Microsoft Run and RunOnce registry keys](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys) and [Microsoft notification area guidance](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area).
- **Validation:** Unit/integration tests cover policy boundaries, filtering, persistence, cancellation, privacy and authorization. A real Windows smoke checks the GUI subsystem, tray registration, single companion, crash recovery and Stop. Real sign-out/sign-in and iPhone Lock Screen delivery remain physical acceptance checks.
